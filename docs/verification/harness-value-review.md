# Harness controls: explicit decision matrix

Northstar — 2026-10-02. Recommendations, not deployment claims.

**SUPERSEDED ANALYSIS:** All historical percentages and ownership recommendations below are withdrawn. Use [the full harness ownership audit](remaining-use-case-decisions.md). In particular, agents own Git merges, conflicts, integration correctness, test selection and review arrangement. These older rows remain only as historical source-status notes.

**Estimate basis:** Planning estimates for the next 100 attempted ordinary backlog items in this actively changing harness, not measured incident rates. Every factor in the calculations is an explicit judgment assumption unless marked deterministic/proven. The arithmetic makes the assumptions inspectable; it does not validate them. Rates describe items affected, not dollars or defect severity. Rows overlap and must not be added. A harmful unauthorized write can outweigh several recoverable false blocks.

**YAGNI rule:** If no credible incremental benefit over the listed simpler alternative is demonstrated, assign **0% credited benefit and REMOVE** the optional control. This is a design decision, not a claim that real-world failure is impossible. For kept controls, the estimate describes the relevant failure if that protection is absent. For removed controls, the comparison preserves the alternative's essential protections. Removing byte equality, for example, still requires semantic identity validation.

**How estimates drive the recommendation:** Keep the small required authority, recovery, review, and spending controls because their failure has concrete impact. Simplify a kept control when its own false-block risk is material. Optional layers with 0% credited benefit lose even before their engineering cost is counted. Future maintenance, model calls, and failure recovery count as costs; sunk implementation effort does not justify retention.
