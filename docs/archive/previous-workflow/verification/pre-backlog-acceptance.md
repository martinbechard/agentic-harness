## Execution and evidence contract

Exercise a clean installed wheel through its public CLI in isolated fixture projects. Use real subprocesses, local Git, provider operations and validators, files, locks, graph checkpoints, and telemetry ingestion. Control only the external CLI/model boundary with a deterministic subprocess double that emits native protocol/session evidence. Do not bypass production validators to establish system acceptance. Run both applicable legacy and graph paths; label unsupported paths explicitly.

Each completed scenario must link a reproducible command, test or saved result, wheel identity, actual final state and effect counts, boundary substitutions, and remaining findings. Inject interruptions around durable writes and external effects, then demonstrate recovery to the intended outcome without repeating completed effects. Assert invocation and effect counts: status and unchanged idle produce zero agent calls, and restart does not repeat completed calls. Uncertain submission must reconcile or produce an actionable hold without duplicate launch; this is not a promise of exactly-once external execution. A rejection-only test does not prove successful recovery. No paid or real-backlog retries are required for this matrix.

Existing tests below are supporting candidates, not an assertion that all their coverage or current results have been verified. “Pending” means composed installed evidence has not been established.
